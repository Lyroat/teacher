# 标绿稿输出契约

本文规定大纲标绿稿的固定产物形态。生成或大改标绿稿前必须读取。

## 定义

“标绿稿”是进入大纲/石墨流转的精炼讲解稿。正文里的引入、设问、知识讲解、拓展、大总结都属于标绿内容，但 Markdown 中不添加任何绿色背景、红色 span 或其他可视化高亮。

## 字数

> 本节是全套 Skill 字数规则的**唯一权威来源**。SKILL.md、`interaction-design.md`、`self-check.md` 和 `scripts/check_highlight_draft.py` 只引用本节，不得另行定义一套数值。

```text
目标：约 1200 字
硬性范围：1170—1230 字
```

### 怎么数一个字

- **标点符号计入。**逗号、句号、分号、冒号、顿号、破折号、引号、括号、感叹号、问号都算 1 字。
- **汉字逐字计入。**
- **连续的字母或数字串按 1 字计。**「2019」算 1 字，「6.0」的两个数字段各算 1 字、小数点另算 1 字，「O₂」的下标属于符号、单独计。
- **空白不计。**空格、换行、缩进都不算。
- Markdown 语法符号在统计前先剥掉，不计入：`**加粗**`、`` `代码` ``、列表符号、表格竖线。

手工核对时按上面的规则数，结果应与脚本一致。

### 数哪些区域

统计方式是**正向白名单**：只统计下面明确列为“计入”的区域，其余一律不计入。不使用“排除已知例外、其余全算”的反向方式。

计入正文字数：

- 各关键问题 H2 小标题下的正文讲述内容
- 互动探索表格**之后**的解释、纠偏或确认式讲解（归属于表格前的那个关键问题）

不计入正文字数：

- `# <主题> E<集数> 标绿稿` 主标题和各级小标题
- `主线问题：……` 等元信息行
- `## 【引入】` 模块
- `## 【互动探索】` 表格
- `## 【大总结】` 模块
- `**【趣味拓展】**` 与 `**【/趣味拓展】**` 标记范围内的内容
- 交付时临时添加的 `（回答主线问题）` 标注

`scripts/check_highlight_draft.py` 按上述白名单输出分项统计，交付时可直接引用：

```text
字数分项：
  文件元信息：21 字（未计入）
  【引入】：76 字（未计入）
  关键问题1：207 字
  关键问题2：768 字
  【互动探索】表格：338 字（未计入）
  关键问题3：203 字
  【大总结】：225 字（未计入）
  ── 合计计入：1178 字（目标 1200，范围 1170—1230）
```

另外两条派生规则：

- 单段 180 字上限只约束【引入】和关键问题正文；【大总结】另有 200—250 字要求，不受该上限约束。
- 问题句总数按可朗读口播范围统计，含【引入】、关键问题正文、互动后正文和【大总结】。

补足与精简：

- 低于 1170 字时补足核心解释，不靠重复表达或框架外拓展凑字数。
- 高于 1230 字时按“先诊断、后压缩、再回归检查”流程处理，不得机械删句。
- 字数缩减时必须保证语言通顺、可读性强，没有逻辑跳跃，让 9-12 岁学生能够听懂、看懂。
- 字数达标不得优先于逻辑完整性。字数超限只触发诊断和压缩流程，不直接触发删句。

## 字数不达标时的处理流程

**默认动作是只诊断、只给建议，不自行改动原文字数。** 这条优先于“把字数改进范围内”。只有用户明确说“帮我删到字数内”“按你的建议改”之后，才动原文。

严禁的做法：

```text
超过字数 → 从正文中间删句 → 重新统计 → 直接交付
```

标绿稿的知识通常是“现象—机制—结论”的解释链。机械删句会让稿件形式上通过字数检查，但科学逻辑已经断裂：现象保留而原因被删、“因为……所以……”只剩一半、结论失去证据支持、代词和转折词失去指向。这比单纯超字数更严重，因为人类教研只看最终稿不一定能发现被删掉的桥梁。

### 超出上限（高于 1230 字）

第一步，诊断。把超出的字数定位到具体段落，并给每段归类：

- 核心知识：框架 bullets 要求的主干内容
- 逻辑桥梁：见下方清单
- 重复表达：同一个意思在前后文出现了两次
- 修辞与口语填充：不承载信息的语气词、排比、感叹
- 框架外拓展：框架 bullets 里没有的补充例子或知识

第二步，按固定顺序提出压缩建议，不跳步：

```text
删除重复句
→ 压缩修辞和口语填充
→ 合并同义句
→ 缩短非关键例子
→ 压缩框架外拓展
→ 最后才考虑删除整段
```

第三步，把诊断结果和压缩建议交付给人类教研，等确认。

### 不得自动删除的“逻辑桥梁”

以下内容默认属于逻辑桥梁。即使人类教研已授权压缩，也不能优先删这些：

- 现象到机制之间的解释
- 机制到结论之间的推导
- 关键问题之间的真实过渡
- 互动探索后的独立解释
- 类比与科学概念之间的对应关系
- “因为”“因此”“这样一来”等因果词两侧的必要内容
- 主线问题的最终回答依据

### 低于下限（低于 1170 字）

同样默认只给建议，不自行补写。建议要指出补在哪个关键问题下、补什么类型的内容（缺失的机制解释、缺失的例子、缺失的影响），不靠重复表达或框架外知识凑字数。

### 已授权压缩后的回归检查

人类教研确认压缩方案后，改完必须重新执行一次完整检查，不能只重新统计字数：

1. 重新运行 `scripts/check_highlight_draft.py`
2. 重新按 `self-check.md` 全表自查
3. 重点复查四项：因果链是否完整、代词和转折词是否还有明确指向、删除互动探索表格后是否仍能顺读、主线问题是否仍被正文回答
4. 交付时说明删了什么、删在哪里

### 压缩到底仍超限时

如果压缩后仍高于 1230 字，且继续删减会影响知识覆盖、因果链、互动衔接或主线问题回答，停止压缩并报告：

```text
当前核心内容无法在 1170—1230 字范围内完整保留。
需要由人类教研决定：放宽字数，或明确删减某个知识点。
```

## 必备结构

```markdown
# <主题> E<集数> 标绿稿

主线问题：...

## 【引入】
...

## 关键问题1：<框架原文>
...

## 【互动探索】

| 项目 | 内容 |
| --- | --- |
| 互动探索位置 | ... |
| 探索问题 | ... |
| 预测问题 | ... |
| 选项 A | ... |
| 选项 B | ... |
| 正确答案 | ... |
| 操作探索 | ... |
| 观察分析 | ... |
| 得出结论 | ... |

...

## 关键问题2：<框架原文>
...

## 【大总结】
...
```

## 关键问题标题

- 每个关键问题必须逐字保留框架原文，作为 H2 小标题。
- 格式为 `## 关键问题N：<框架原文>`。
- 不使用自拟小标题替代关键问题。
- 若框架关键问题含 `⭐` 或 `【】` 标签，标题中必须保留。
- 标题下方不要再重复一次关键问题原文。
- 编号从 1 开始连续，不跳号、不重复、不倒序。

### 标题里的标签不进正文

H2 标题是**给教研看的结构标记**，不是口播内容。`⭐` 和 `【看到现象】【追问原因】` 这类标签留在标题里，但正文里不出现任何一个标签的字样。

正文要做的是**落实标签对应的思维动作**：标题挂了【追问原因】，正文就得真的追问原因；不是在正文里写一句“接下来我们来追问原因”。

标签写在框架原文的前面还是后面属于排版差异，不算改动原文。

## 引入

- 引入必须紧扣主线问题，使用现象、趣味内容或认知反差。
- 引入可以来自学生常见误区，但不能为了误区素材偏离本集主线。
- 禁止用“今天我们来学习……”开头。
- 引入最后的疑问或悬念必须能被正文第一段自然接住。
- 不要在引入中提前讲出后文要揭晓的核心答案。

## 大总结

- 末尾必须有 `## 【大总结】`。
- 大总结约 200 字，建议范围 200—250 字。
- 不计入正文总字数。
- 不受 180 字段落上限约束。

以下几条脚本查不了，交付前逐条人工核对，**不要用关键词匹配代替判断**：

| 要求 | 怎么判断 |
| :--- | :--- |
| 只总结标有 `⭐` 的关键问题对应的重点知识 | 逐句问：这句对应哪个 `⭐` 关键问题？对不上就删 |
| 回答了主线问题 | 把主线问题念一遍，看大总结里能不能找到答案 |
| 不引入新知识点 | 逐句问：这个说法正文里出现过吗？没出现就是新知识 |
| 不做泛泛价值升华 | 出现“让我们一起保护地球”这类句子就删 |
| 不写衔接句 | 不写“回到开头的问题……”“我们刚才已经知道了……” |
| 句数合适 | 2—4 句，每句对应一个明确结论 |

判断标准是“这句话在说什么”，不是“这句话有没有某个词”。“保护土壤，从现在做起”不含“升华”二字，但它就是泛泛升华。

## 互动探索与正文的边界

【互动探索】是**可抽离的插入模块**，不是正文的一部分。这一条最容易在实操中被违反：写着写着，把知识讲解搬进了互动表格，正文只剩下引出实验和总结实验，知识本身没讲。

### 抽离测试

把【互动探索】表格整块删掉，然后读剩下的正文。剩下的正文必须**独立讲清**四件事：

1. **观察到了什么现象**——不能只写“通过实验我们发现”，要把现象本身说出来。
2. **为什么会这样**——机制或原理必须在正文里，不能只在表格的「预期发现」里。
3. **这说明了什么**——结论要落在正文，不能靠表格的「得出结论」行代替。
4. **与主线问题的关系**——这个结论怎么帮着回答本集主线问题。

四件事有任何一件只存在于表格里，就是互动模块替代了正文，必须把知识讲解搬回正文。

可以用脚本输出抽离后的正文辅助判断：

```bash
python3 scripts/check_highlight_draft.py <draft.md> --interaction-test
```

脚本只输出材料，判断仍要人做。

### 禁止的依赖表述

正文里不得出现指向互动模块的句子，因为删掉表格后这些句子会失去指向：

- ❌ “刚才的探索告诉我们……”
- ❌ “你刚才看到，土壤里的幼苗没有倒。”
- ❌ “上面的实验说明……”

改成不依赖表格也成立的写法：

- ✅ “土壤能把植物的根固定住，风吹过来时植物不会倒。”

正文和表格讲同一件事不算重复——表格是让学生自己做一遍，正文是把结论讲清楚。两者都要完整。

### 表格之后的正文

【互动探索】表格结束后紧接的讲解文字**计入正文字数**，归属到最近的那个关键问题。表格本身不计入。

## 趣味拓展

趣味拓展**不是必需的**。写不出自然贴合主线的内容就不写，不要为了有这个模块硬凑一段。

规则：

- 每篇**最多一处**。
- 单处不超过 100 字。
- 必须服务主线问题，或直接支撑某个关键问题的理解。和主线无关的冷知识不写。
- 不计入正文字数。
- 起止标记统一为 `**【趣味拓展】**` 和 `**【/趣味拓展】**`，两个标记必须配对出现。少了闭合标记，后面的正文会被整段算作趣味拓展从而漏计字数，脚本会报 FAIL。
- 不得用趣味拓展装本该进正文的主干知识。判断方法：删掉这段，主线问题还答得完整吗？答不完整就说明它是主干知识，该进正文。

## 默认保存位置

```text
01-outputs/<主题>/04-大纲/E<集数>/<主题>_E<集数>_标绿稿.md
```

用户指定路径、版本号或文件名时，以用户要求为准。
