# 互动模块设计

本文规定【互动探索】的定位、表格格式和前后衔接。生成或修改互动模块时必须读取。

## 总原则

- 互动探索服务重点知识理解，不承担完整题目训练。
- 使用 Markdown 表格。
- 表格内容不计入正文字数统计（见 `output-contract.md` 的「字数」一节）。
- 互动探索是可抽离模块：删除表格后，表格前后的正文仍要能自然连读。
- 表格后的第一句不能只依赖表格成立，例如不要只写“你刚才看到的是……”或“选 B 更接近答案……”。应先用独立陈述接住前文，再自然揭示互动结论。

## 【互动探索】定位

互动探索通常放在知识精讲偏前或框架指定位置。它的节奏是：

```text
提出探索问题
→ 预测
→ 操作探索
→ 观察分析
→ 得出结论
→ 知识精讲接住并展开解释
```

如果框架已有【互动探索】或【交互探究】：

- 保留框架给定位置。
- 不拆散互动探索及其前后直接相关的知识点。
- 模块后必须紧接知识精讲，用互动发现解释重点知识。

如果框架没有互动探索：

- 只设计一个轻量、服务重点知识理解的小探索。
- 不新增复杂实验、材料准备或完整探究任务。

## 【互动探索】预测题

- 必须有 1 个预测问题和备选答案。
- 其中一个选项对应学生可能有的直觉误解，一个对应正确判断。
- 选项尽量不超过 15 个字。
- 预测题必须服务接下来的操作探索，不能像普通知识问答一样脱离操作。
- 预测题要让学生能先判断，再通过操作或观察修正判断。

### 题型

表格里必须写明题型，因为**题型决定了「正确答案」怎么填**，写错会让制作环节做出错误的交互。

| 题型 | 选项数 | 正确答案写法 |
| :--- | :--- | :--- |
| 单选 | 2—4 个 | 单个字母，如 `B` |
| 多选 | 3—4 个 | 多个字母，如 `ABC`；若为全选要写明 `ABC 全选` |
| 二选一预测 | 2 个 | 单个字母，如 `A` |
| 判断 | 2 个（对/错） | `对` 或 `错` |

- 「选项 C」及以后是**可选行**。只有两个选项时直接省略该行，不要写成 `| 选项 C | 无 |`。
- 「正确答案」必须和题型对得上：单选题填了两个字母、多选题只填一个字母，都是错的。
- 多选题的正确答案是全选时要写明，否则容易被当成漏填。

## 【互动探索】表格

```markdown
## 【互动探索】

| 项目 | 内容 |
| --- | --- |
| 互动探索位置 | 放在“……”之前/之后 |
| 探索问题 | …… |
| 预测问题 | …… |
| 题型 | 单选/多选/二选一预测/判断 |
| 选项 A | …… |
| 选项 B | …… |
| 选项 C | ……（可选，两个选项时删除本行） |
| 正确答案 | 按题型填写 |
| 操作探索 | …… |
| 观察分析 | …… |
| 得出结论 | …… |
```

## 衔接检查

完成互动模块后，做删除测试：

删除【互动探索】整个表格，只保留前后正文，检查两件事：

1. **能否顺读**——前后文衔接是否断裂。如果断裂，优先改表格后的第一句，让它先接住前文，再带出互动结论。
2. **知识是否还在**——剩下的正文是否仍独立讲清了现象、原因、结论和与主线的关系。判断标准见 `output-contract.md` 的「互动探索与正文的边界」。

第 2 条比第 1 条更容易出问题：读起来顺了，但知识被搬进了表格，正文只剩引出和收尾。

可以用脚本输出抽离后的正文辅助判断：

```bash
python3 scripts/check_highlight_draft.py <draft.md> --interaction-test
```
